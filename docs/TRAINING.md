# 학습 설정 · 데이터 파이프라인

`config/training_config.yaml` · 체크포인트 파일명 · TensorBoard 로그에서 직접 읽은 실측값입니다.

## 데이터 파이프라인

```
음원 확보 → 반주·잡음 분리 → 음량 정규화 → [전량 청취 검수] → 슬라이스 → 학습
   자동          자동            자동          수작업            자동      11일
```

| 단계 | 도구 | 산출물 |
|---|---|---|
| 1. 음원 확보 | 크롤링 / 동의받은 녹화본 | 원본 음원 |
| 2. 반주·잡음 분리 | **UVR5 · Spleeter 5stems** | 보컬 트랙 |
| 3. 음량 정규화 | — | 화자별 레벨 통일 |
| 4. **전량 청취 검수** | **헤드셋 · FL Studio** | 문제 구간 제거 |
| 5. 슬라이스 | `binarize.py` | **2,527 클립** |
| 6. 학습 | diff-svc | 화자 5명 · 약 194시간 |

**4번이 자동화하지 않은 유일한 구간입니다.** 분리·정규화까지는 도구가 해주지만, "이 구간이 학습에 쓸 만한가"는 사람이 들어야 압니다.

## 학습 설정 (5개 모델 공통)

| 항목 | 값 | 비고 |
|---|---|---|
| 인코더 | **HuBERT-Soft** (`hubert_soft.pt`) | 공개 사전학습 |
| 보코더 | **NSF-HiFiGAN** | 공개 사전학습 |
| 샘플레이트 / hop | **24kHz / 128** | 기본 512 → 촘촘하게 |
| Diffusion | `timesteps` 1000 · WaveNet **20층 × 256채널** | 기본 384 → 축소 |
| f0 | **50 ~ 1100Hz** · `parselmouth` | |
| 학습률 / 배치 | **4e-4 / 10** · AMP | |
| 체크포인트 | 2,000 step마다 · 최근 10개 보관 | |

**`hop_size`를 낮춰 시간 해상도를 올리고, `residual_channels`를 줄여 모델 폭을 낮춘 조합**입니다. 같은 VRAM에서 가창의 음정 변화를 더 촘촘히 잡으려는 설정입니다.

## 학습 곡선에서 확인한 것

로그가 온전한 3개 모델의 `tr/mel` 을 구간별로 평균한 값입니다.

| 구간 | 평균 mel loss (C) |
|---|---|
| 0 ~ 2.5만 step | 0.0450 |
| 2.5 ~ 5만 | 0.0258 |
| **5 ~ 10만** | **0.0214** |
| 10 ~ 20만 | 0.0207 |
| 70 ~ 100만 | 0.0199 |

**5만 step 부근에서 사실상 평탄해집니다.** 이후 95만 step(약 30시간)을 더 돌렸지만 손실은 4~10% 개선에 그쳤습니다.

> 당시엔 지표를 보지 않고 최대한 오래 돌리는 게 낫다고 생각했습니다. 지금이라면 검증 손실을 보고 조기 종료를 걸었을 것입니다.
>
> 다만 **mel loss가 음질의 전부는 아닙니다.** 지각 품질은 손실이 평탄해진 뒤에도 좋아질 수 있어, "5만이면 충분했다"가 아니라 **"손실 기준으로는 평탄했다"** 까지만 말할 수 있습니다.

## 모델은 수정하지 않았습니다

원본 `diff-svc` 와 작업 폴더를 파일 단위로 비교한 결과, 바뀐 것은 `training/config.yaml` · `infer.py` · `inference.ipynb` 뿐이었습니다.

**이 프로젝트의 기여는 데이터 확보·정제 · 학습 설정 · 학습 운영 · 결과 검증입니다.**
아키텍처를 고친 프로젝트가 아닙니다. 실제로 결과를 바꾼 것은 모델이 아니라 데이터였습니다.
